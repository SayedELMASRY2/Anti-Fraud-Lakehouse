BUSINESS & TECHNICAL CHALLENGE

Problem Statement: The FinTech Ingestion Dilemma

Financial institutions manage disparate data sources with conflicting throughput, latency, and schema requirements.

Three Operational Bottlenecks

1. Tri-Modal Ingestion Conflict

Real-time payments (100+ TPS) cannot wait for batch windows, while dimensional data (users, cards) resides in relational ACID databases.

2. Relational Write Exhaustion

Traditional architectures insert streaming transactions directly into RDBMS tables, causing connection pool deadlocks and query latency spikes.

3. Downstream Analytical Desync

Delayed or uncoordinated ingestion results in fraud models scoring transactions against stale customer profiles.

RISK: Fraudulent transactions slip through before model scores

Fragmented Legacy Ingestion Architecture

VERIFIED PROJECT INVARIANT: Relational databases are built for transactional ACID state, not for high-velocity payment streaming pipelines.
UNIFIED SOLUTION BLUEPRINT

Our Solution: Multi-Path Ingestion & Lakehouse

Decoupling streaming ingestion from relational persistence to guarantee linear scale, zero lock contention, and sub-10ms scoring.

DECISION LOG

Architecture Trade-Offs & Technology Selections

Deliberate engineering decisions made between conflicting technical paths to maximize performance and maintainability.

Kafka vs RabbitMQ

Selected Kafka for partitioned persistent log storage and replayability over RabbitMQ AMQP routing.

→ Replay up to 7 days

Zero-DB-Inserts vs Direct Database Logging

Bypassing RDBMS inserts prevents connection pool exhaustion and deadlocks under burst traffic. PostgreSQL is reserved for demographic master data via Debezium CDC.

→ Eliminates 100% of OLTP lock contention

LightGBM vs Deep Learning (MLP/LSTM)

LightGBM evaluates in 1.4ms on standard CPU workers with 99.4% ROC-AUC, avoiding heavy GPU cluster overhead, cold-start model latency, and non-deterministic deep learning delays.

→ CPU efficiency with sub-10ms SLA

Databricks Lakehouse

Delta Lake unified storage eliminates ETL sync between batch lakes and relational analytical marts.

→ Single source of truth
VERDICT: Engineered for extreme horizontal scalability, sub-10ms SLAs, and low total cost of cloud ownership.
